# Treatment — proposed, not approved

## Three directions

1. **The folder unfolds (recommended).** Open on one ordinary folder of photos. A real terminal action initiates a visual unfolding into the actual searchable map; a search narrows it to a visible result. Peak: the same photos become navigable. End: Atlasfold 1.0, offline, MIT, three platforms. Restrained tactile motion and a warm, precise score. Risk: the real map or search may differ from the imagined transition. Compare at the sketch gate.
2. **Find the photograph.** Open with a specific photo as a question, then follow a real search through Atlasfold to its result. Peak: the sought photo is found in context. End on the product name and verified release details. Intimate, focused, light sound. Risk: requires a real example and a query the product actually supports; do not promise a type of search without evidence.
3. **A new view of a folder.** Start with a grid of photos; the grid becomes a map, then the actual interface resolves in place. Peak: map and original folder are visibly connected. End with the product and licence. Spare, graphic, music-led. Risk: an illustration could be mistaken for the product; label it and show an actual capture.

## Proposed governing operation
A collection changes from a folder into a searchable map. Keep the same identifiable photos through the transition. An illustrated transformation explains the relationship; the real capture proves the behavior. It does not imply automatic location detection, semantic search, speed, or a specific interface.

Tests are provisional: operation is a folder → action → map sequence; truth depends on capture; decoding requires a newcomer to describe that sequence after one muted viewing; specificity depends on the actual Atlasfold output and may require revision after inspection; muted comprehension depends on clear action, result and readable labels. None has yet been viewer-tested.

## Structure and draft script
A question becomes a visible result. The turn is the product action; the peak is the search result in the map; the ending tells the viewer what Atlasfold is and where to find it. The same photo anchors beginning and end. Voice is optional; all essential information appears on screen. Exact command, query and CTA await the actual repository.

| Time | Picture and sound | Draft text / evidence |
|---|---|---|
| 0–5 | A folder of photos, one photo held as an anchor; music starts quietly. | “A folder of photos.” No product claim. |
| 5–11 | Real terminal capture, command shown only once verified. | “Meet Atlasfold.” Product name: F1. |
| 11–20 | Labelled illustration connects folder to map, then resolves to real output. | “Build a searchable map.” F1. |
| 20–31 | Hold on real map; show a verified search and result. Let the result be inspected. | Search demonstration: F1, subject to product verification. |
| 31–38 | Return to the anchored photo within the map. | “Runs offline” and “macOS · Windows · Linux.” F2–F3. |
| 38–45 | Clear end card, quiet resolved finish. | “Atlasfold 1.0 is out” / “Open source · MIT licensed” / verified repository address when supplied. F4–F5. |

Timings are a draft, not a tested reading window. Prefer no narration unless a timed rough shows it helps; captions accompany any narration. Sound should support actions without turning every movement into a click. The cover proposes the anchor photo alongside the map and “Atlasfold 1.0”; actual map appearance must be verified.

## Viewer bar
For each round record a named viewer, version, device, size, sound state and unprompted words; approver marks each met, not met or unknown. Understanding: viewer can describe folder → searchable map and Atlasfold's role. Specificity: they identify the actual map and search, rather than only generic photo organisation. Experience: they report a response worth having. Earned payoff: the result connects to the opening photo. Truth: inferred behavior matches verified product evidence. Afterimage: viewer recalls Atlasfold and the folder-to-map idea, immediately or after a recorded delay. Unknown remains open. Make two or three alternatives for the weakest three seconds and compare in motion before revising.
