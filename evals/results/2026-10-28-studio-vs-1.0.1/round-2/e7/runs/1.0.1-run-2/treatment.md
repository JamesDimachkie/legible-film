# Treatment — From folder to findable

The viewer sees an ordinary photo folder become a searchable map through a real Atlasfold operation. The change is from an unknown collection to an understandable result; the evidence is the product's actual input, action and output. This does not establish what kind of map it is, how search works, or how quickly it runs.

## Three concepts

| Lens | Opening | Product event and proof | Peak and ending | Risk |
|---|---|---|---|---|
| Product in use | A folder of photos; what can you make from it? | Real command and resulting searchable map | A search produces a verified result; invite viewers to the repo | Fine interface details may be unreadable in a feed |
| Relational analogy | Loose photos gather into an ordered field | Visual arrangement gives way to real product output | The real map resolves from the folder | Implies geographic locations or relationships the product may not support |
| Reframe | A folder is a starting point, not the end | A single photo collection moves from input to searchable output | Return to the same collection as the result | Abstract transformation may obscure the product |

Chosen: product in use, borrowing the reframe's visual continuity. It makes the capability concrete. The same sample collection remains identifiable from beginning to end; a visual thread follows it into the actual output. Illustration ends when the real product capture starts, and is labelled where needed. No invented map, command, query or search result.

Operation: because Atlasfold builds a searchable map, the film changes the presentation of one photo folder into the actual map produced by Atlasfold. The input remains recognisable; its representation changes. Do not imply an unverified connection between images.

Tests: operation — one folder, one action and one real result can communicate the idea; truth — capture and verify the real operation before production; decoding — a first-time viewer should say “it makes a searchable map from photos,” tested with a person; specificity — the actual output and command should make the piece specific to Atlasfold, subject to inspecting the product; muted — the action, result, name and invitation carry the story without sound. These are design hypotheses, not passed viewing tests.

Structure: setup → action → result → search → release. Turn: the actual output appears. Peak: a real query and its actual response make search visible. End: hold the name, version and repository invitation. If search cannot be demonstrated honestly within the time, show the verified output and avoid inventing a search interaction.

## Script and approximate score

| Time | Picture and motion | On-screen text | Sound and lead |
|---|---|---|---|
| 0–5 | A recognisable folder of synthetic photos; Atlasfold name appears on the first frame. | “Atlasfold” / “A searchable map from your photos” [product] | Quiet musical opening; action leads. |
| 5–12 | Move in to a legible real terminal capture, showing the verified command and input. | Actual command only after verification; “Folder → map” [product] | Music builds gently; one restrained action cue. |
| 12–20 | Show the real operation and resulting map; preserve actual time or label any compression. | “Build a searchable map” [product] | Action leads, result lands with one soft cue. |
| 20–29 | Show a real search and result, framed close enough to read; hold the result. | Verified interface text only. | Music supports; no dense effects. |
| 29–37 | Keep the result visible while facts appear one at a time. | “Runs offline” [offline]; “macOS · Windows · Linux” [platforms] | Music leads, then settles. |
| 37–45 | Simple end card, generous hold, cover-ready identity. | “Atlasfold 1.0” [release]; “Open source · MIT licensed” [license]; “Explore the repository” [invitation, no factual claim]. Add verified URL when supplied. | Resolve and leave a clean tail. |

These timings are a draft, not a cue export. On-screen text will receive in/readStart/readEnd/out times after design, and picture and sound will share one timing source. No voice is scripted; if narration is later chosen, create matching sidecar captions and test against the audio. The opening and ending should be legible at phone-feed size. Proposed cover: Atlasfold name and “A searchable map from your photos” beside an identifiable photo folder and a crop of the verified output.

Visual direction: a quiet dark canvas, generous typography, one accent used to trace the input into the result, and subtle camera movement driven by the real interaction. Final colours, type and logo must come from supplied brand assets or an explicitly proposed fallback. No stock footage is necessary to explain the product.

Open evidence: repository and release URL; runnable build and supported commands; what the map looks like and how search works; permission and source for sample photos; brand files. First-viewer questions: What did Atlasfold make? What did the search do? What would you do next?
