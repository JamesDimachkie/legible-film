# Treatment — provisional

The film changes a folder of photos from a collection into something a viewer can search on a map. Evidence must be a real, repeatable product run from input to output. It does not establish what data Atlasfold extracts, what searches it supports, or how quickly it works.

Three directions to compare as rough moving sketches, not final design:

1. **The folder becomes a map.** Open on a real folder, run the real command, then reveal the actual searchable result. Peak: a search visibly changes the result, if the product supports that behavior. End on Atlasfold 1.0 and the platform/license facts. Restrained, tactile motion and a warm instrumental bed. Risk: the actual interface might not be visually legible; we must capture it before promising this sequence.
2. **One photo, a place in a larger picture.** Start with one photo, pull back to a folder, then reveal the actual map. The peak joins that photo to its real result. Delicate photographic look and sparse sound. Risk: this could imply geolocation or a specific association that has not been verified; use only if real output proves it.
3. **A question finds its way.** Open on a concrete search question grounded in a verified supported query. Run the CLI and show its actual answer. Peak: the visible result resolves the question. Typographic, high-contrast look; music builds gently. Risk: no supported search query is known yet.

Recommended provisional direction: 1, because it shows the named input and output with the fewest assumptions. The operation is reveal: the folder stays identifiable while the real result becomes visible. No animation may imply a feature or process that the capture does not show. Take the human-scale photo detail from 2 if verified.

Tests, pending real capture and viewer sketches: operation—folder, command and result must read even without decoration; truth—only verified capture is evidence; decoding—a new viewer should describe input, action and output; specificity—the actual command and map must identify Atlasfold rather than a generic tool; muted—cause and outcome remain visible without narration. If the product fails, the expected map or search result will not appear; the actual test must be defined after inspection.

Structure: curiosity, action, result, practical facts, invitation. Turn at the real command; peak at the verifiable search result. End gives the name and a verified repository address, if supplied. The folder is the visual thread. The cover shows the name beside a legible representative product result, pending evidence.
